# Event store drops members inherited from intermediate event and aggregate base classes

> Issue: [#183](https://github.com/chA0s-Chris/Chaos.Mongo/issues/183)

## Rationale

`MongoEventStoreSerializationSetup.RegisterClassMaps<TAggregate>` builds each event class map directly on top of the `Event<TAggregate>` class map and each `Aggregate`-derived aggregate class map directly on top of the `Aggregate` class map. `AutoMap` maps only members declared on the class itself, so members declared on any class in between are neither stored nor read back, silently losing data since the event store was introduced. Consumers who register their own class maps first are not affected.

The goal is to register event and aggregate class maps along their real CLR hierarchy, so inherited members round-trip, without changing the discriminators of observational events deriving directly from `ObservationalEvent<TAggregate>`, pre-registered class maps, or the readability and integrity of documents already stored.

## Acceptance Criteria

- [x] Events derived from an intermediate event class store and read back the members declared on every intermediate class, covered by automated tests.
- [x] Aggregates derived from an intermediate class between them and `Aggregate` store and read back the inherited members in the read model and in checkpoints, covered by integration tests.
- [x] A derived event registered via `WithEvent` before its registered intermediate base stores the same members and the same discriminator array as one registered after it, and the intermediate type keeps the discriminator configured for it in either order, with tests using a separate type pair per order.
- [x] An intermediate event type not registered via `WithEvent` appears in the discriminator array with the driver's default discriminator, with a test.
- [x] Registration throws `InvalidOperationException` naming both types when two registered class maps deriving from `Event<TAggregate>` share a discriminator, including class maps of earlier registrations of the same aggregate, with tests.
- [x] Observational events deriving directly from `ObservationalEvent<TAggregate>` keep their current discriminators, observational events with intermediate bases of their own store those bases' members like other events, and the repository's replay exclusion of observational events is unchanged for both, with tests.
- [x] Class maps registered by the consumer before the event store, including intermediate ones, are used unchanged, with tests.
- [x] Event documents stored with the previous, shorter discriminator array still deserialize to the correct type, with a test.
- [x] The reserved `_integrity` element check covers every intermediate class map in the resulting hierarchy, whether pre-registered or registered by the event store, and rejects a collision before the event store registers the colliding class map, with tests.
- [x] `docs/event-store.md` documents that inherited members are now stored, the changed discriminator arrays of newly appended derived events, the default discriminator of unregistered intermediate types with the recommendation to register them explicitly, the rejection of shared discriminators and how to resolve it, and that data dropped by earlier versions cannot be recovered.

## Technical Details

- **Recursive registration (new private helper):** registers a type on top of its direct CLR base type's class map, recursing to register missing intermediate types first. Recursion stops at `Event<TAggregate>` for events and at `Aggregate` for aggregates; both base maps keep their current configuration. A type whose class map is already registered is used as-is and not modified. Missing types are registered along the whole CLR chain up to the root, including above pre-registered class maps, before any class map in the chain is looked up, since `BsonClassMap.LookupClassMap` freezes a map and auto-registers its missing bases with default settings.
- **Discriminators:** when the event store registers a type present in `options.EventTypes`, it applies the configured discriminator via `SetDiscriminator`, whether as a leaf or as another event's intermediate base, so `WithEvent` order does not matter. Other intermediate types keep `AutoMap`'s default (`[BsonDiscriminator]` if present, otherwise the class name, including type arguments for generic types, e.g. `Name<String>`). Because `Event<TAggregate>` is the root class, newly appended derived events store arrays like `["Event<X>", "ProbeBase", "ProbeDerived"]`.
- **Discriminator collisions:** registering class maps for intermediate types adds their default discriminators to the driver's registry, so the event store rejects a discriminator that two types in the resulting hierarchy share. Otherwise the driver accepts the registration but fails every read of that discriminator with "Ambiguous discriminator", for example when `OrderPlacedV2 : OrderPlaced` is registered as `"OrderPlaced"` and `OrderPlaced` is no longer registered. Class maps are process-global, so the check covers every registered class map deriving from `Event<TAggregate>`, including pre-registered ones and those of earlier registrations of the same aggregate.
- **`ObservationalEvent<TAggregate>` is transparent:** it declares no stored members, so it gets no class map in the chain; a type deriving directly from it is registered on top of `Event<TAggregate>`. Discriminators of observational events deriving directly from it therefore stay `["Event<X>", "<Name>"]`; intermediate bases between `ObservationalEvent<TAggregate>` and a concrete observational event are registered like any other intermediate type. `ObservationalEventDiscriminators` and the repository's exclusion filter compare the last array element, so they need no change.
- **Aggregates:** only aggregates deriving from `Aggregate` change. Aggregates implementing `IAggregate` directly keep the existing `RegisterClassMap<TAggregate>` path. `EnsureAggregateMapsRevision` is unaffected because `Revision` is still declared on `Aggregate`.
- **Reserved-element check:** `EnsureNoReservedElementCollision` already walks the CLR hierarchy; after the change those intermediate maps are actually part of the event's class map chain. Every class map the event store registers, intermediate or leaf, is checked before `BsonClassMap.RegisterClassMap`, so the colliding class map itself is never registered. Class maps registered earlier in the same call are not rolled back, as before. The existing `WithEventStore_PreRegisteredIntermediateBaseMapsReservedElement_ThrowsInvalidOperationException` stays valid.
- **Compatibility:** stored documents are not rewritten, and `EventStreamVerifier` hashes the raw stored documents independently of class maps, so sealed events still verify. Deserialization uses the last discriminator element, so old two-element arrays still resolve. Exception: an inherited member marked `[BsonRequired]` is now mapped as required, so documents stored before the upgrade lack its element and fail to deserialize; the upgrade notes require removing the attribute or migrating those documents first (raised in the #187 review). Inherited event members were never stored and cannot be replayed; existing read models regain such aggregate fields only when later events set them. The PR description must state this, since `CHANGELOG.md` is generated from PR titles.
- **Tests:** event round-trips can be unit tests serializing through `BsonSerializer` after `WithEventStore` registration; read-model and checkpoint persistence of inherited aggregate members need Testcontainers integration tests (see `CheckpointIntegrationTests`). Class maps are process-global, so each test uses its own event and aggregate types.
- **Coordination with #159:** the #159 plan (`ai-plans/0159-tamper-evidence-personal-data.md`, not yet on `main`) states that inherited personal data marks are skipped for class maps the event store registers on top of `Event<TAggregate>`. If #159 is on `main` when this branch is merged, update that sentence here to reflect that event-store-registered class maps now map inherited members; otherwise #159 owns the update.
